# capdisc data guide (for readers and a website)

Labels (cross-verified (kernels) / verified (method) / exact (kernel) / numerically identified / floating-point checked)
follow `VERIFICATION.md`.

Everything here is on GitHub, repo `wkusner/Discrepancy`, branch **`capdisc`**, folder
`capdisc/`. Raw URLs have the form
`https://raw.githubusercontent.com/wkusner/Discrepancy/capdisc/capdisc/<path>`.
Files marked *server only* live on the department server w227 under
`~/Discrepancy/capdisc/` and are **not** on GitHub (see "Getting server data to GitHub").

## What the project does

For N points on the unit sphere S², the spherical cap discrepancy is

    D(X) = sup over closed caps C of | #(X ∩ C)/N − σ(C) |,    σ(C) = (1 − t)/2

for the cap C = {y : ⟨y, w⟩ ≥ t} (Archimedes). D_N = min over all N-point configurations.
The work has four layers, each with its own data:

1. **Search**: find candidate minimizers (many descents; results grouped into classes).
2. **Identification**: high-precision polishing, the exact value as an algebraic number
   (minimal polynomial), exact Gram matrices, and Gröbner bases with msolve.
3. **Proof by computer**: an interval-verified and Arb-verified computation showing that the candidate is the
   global minimum (done for N=5; N=6 running on w227).
4. **Papers**: kept in a separate repository (not part of this one).

Status: N ≤ 4 proved by hand; N = 5, 6 proved (computer-assisted: interval-, Arb- and
Krawczyk-verified; second-kernel cross-checks in progress); N = 7, 8 numerical candidates;
N = 9–12 search values only.

## Conventions (used by every file)

* **Points** are unit vectors `[x, y, z]`, indexed 0..N−1.
* **Gauge (normal form)**: point 0 = north pole `(0,0,1)`; point 1 = `(sin q0, 0, cos q0)`
  with x ≥ 0; point i ≥ 2 = `(sin θ cos φ, sin θ sin φ, cos θ)` with
  `θ = q[2i−3]`, `φ = q[2i−2]`. So a configuration is a vector **q** of length 2N−3.
  In the fundamental domain, (0, 1) is a closest pair, θ₂ ≤ θ₃ ≤ …, and φ₂ ∈ [0, π].
* **Caps.** A "worst cap" is given by the indices `I` of the points on its boundary:
  * |I| = 2: the smallest cap through the pair.
  * |I| = 3: one of the two caps bounded by the circle through the triple.
  * Two encodings occur:
    * *search/critical files*: `kind` = `"up"` (the cap is over-full: `n_closed/N − σ = D`)
      or `"low"` (under-full, `σ − n_open/N = D`), with `t` the signed plane level, so
      σ = (1 − t)/2.
    * *verification files* (in `certificates/`): strings `"Cap(i, j, k)+"` / `"Cap(i, j, k)-"`. The sign selects the
      side of the plane relative to the normal `(x_j − x_i) × (x_k − x_i)`, with i<j<k.
      Pairs are written `"Cap(i, j)+"`. Each comes with an integer **count** n_C of points in
      the cap, so the cap's value is `n_C/N − σ(C)`.
  * To draw a cap, take axis `w` and level `t`. The boundary circle has center `t·w` and
    radius `sqrt(1 − t²)`.
* **Numbers**: `D_float` is a double; `D_60digits` and `D_digits` are decimal strings.
  `minpoly_ascending` lists integer coefficients in ascending order of powers of the
  variable named alongside (usually D itself; the paper's P5/P6 use u = N·D).
  Interval enclosures are `[lo, hi]` pairs of doubles.

## Files on GitHub

### `sphcap/data/critical_configurations.json`: the main data set
`{ "description": str, "classes": [ … ] }`, with 9 classes:
`N5_best, N5_valley, N5_third, N6_best, N6_second, N7_best, N8_best, N8_second, N8_third`.

| field | type | meaning |
|---|---|---|
| `name` | str | id, e.g. `N5_best` |
| `N` | int | number of points |
| `kind` | str | e.g. "sharp minimiser (C2v)" |
| `D_float`, `D_60digits` | float, str | discrepancy |
| `minpoly_ascending` | list[int] or null | minimal polynomial of D (ascending) when known |
| `points` | list[[x,y,z]] | gauge-fixed coordinates |
| `gram_offdiag` | list[float] | upper-triangular Gram entries ⟨x_i,x_j⟩, i<j, row-major |
| `n_active` | int | number of worst caps |
| `rank`, `dim_quotient` | int | rank of worst-cap gradients / 2N−3 |
| `min_multiplier` | float | smallest balance weight λ |
| `sharp` | bool | sharp (strict first-order) local minimum |
| `gram_automorphisms` | int | order of the symmetry group (on the Gram matrix) |
| `active` | list | worst caps: `{I, kind, n_closed, n_open, t, lam}` |
| `symmetry`, `notes` | str | human description |

### `sphcap/data/gram_exact.json`: exact Gram matrices (generated by `jobs/gram_exact.py`)
`{ NAME: {N, D (80 digits), D_minpoly_ascending, gram_pattern, entries:[…], dps, residual, note} }`.
* `gram_pattern` is an N×N matrix of indices into `entries`; the diagonal is −1 and means 1.
  It shows which Gram entries are equal (the symmetry pattern).
* Each entry is `{value (60 digits), minpoly_ascending, in_QD: {denom, coeffs}}`, meaning
  `denom · g = Σ coeffs[i] · D^i`. So every Gram entry is a polynomial in D with rational
  coefficients, of degree < deg(D). Example, N6_best: two of the four distinct entries are
  6D² − 1/2 and 8D² − 8D/3 − 7/9.
* They were found by LLL (600 digits, checked to 590). For N5_best and N6_best they are now proved:
  `certificates/gramcert_*.json` (cross-verified; atlas level 3). The other entries remain numerical
  identifications. The exact
  symbolic parametrizations behind them are in the paper (Section 8):
  * N5: points (0, ±√(1−c²), c), (±√(1−e²), 0, e), (0, 0, 1), so G = {c·e, 2c²−1, c, e, 2e²−1}.
  * N6: the D3-orbit of (a, b, c), with a = (1−6D)/3, c = 2D and b = √(1 − a² − c²).

### `certificates/`: proof artefacts (all small JSON; the folder name is historical, and labels follow `VERIFICATION.md`)
* `localcert_N5_best.json`, `localcert_N6_best.json`: the local verification (Krawczyk-verified, Arb) around each copy
  ("image") of the minimizer in the fundamental domain. Top level:
  `{name, N, box_radius, gauge, verified, kernel, method, label, images:[…]}`. Per image:
  `krawczyk` (bool), `krawczyk_radius`, `D_enclosure` [lo,hi], `q_center` (length 2N−3),
  `caps` (strings), `counts`, `extra_caps`/`extra_counts` (redundant worst caps),
  `others_below`, `counts_frozen_on_box`, `orthants_failed` (0 = pass), `verified`.
* `symcert_<NAME>_img<k>.json`: the symmetric verification per image: `group_order`,
  `orbits` (representative caps), `orbit_caps`, `D_s` [lo,hi] (128-bit), `eliminant_degree`,
  `P_divides_eliminant`, `factors_meeting_enclosure`, `verified`, `kernel`, `label`.
* `proof_N5.json`: the global proof record for N=5. Fields: `T` (threshold);
  `capcert_result` (summary line); `capcert_stamp` (settings and counts, with T in hex);
  `refine` (`input_cells, cells, bounded, sym, boxed, failed, time, verified`); `labels`; `machine`.
  `proof_N6.json`: the same for N=6.
* `pipelineB_N5.json`, `pipelineB_N6.json` (and the earlier local run `pipelineB_N5_local.json`): pipeline B (second kernels): the mesh record of `capcert_arb`
  (`result` line, `done_stamp`) and the mpmath.iv refinement record (`xrefine`), copied verbatim; `xcheck_verdict.py`
  reads them when the server's `results/` files are not present.
* `xcheck_verdict.json`: per N, the checks of pipeline B and `pipeline_B_proves`.

* `gramcert_N5_best.json`, `gramcert_N6_best.json`: the exact Gram matrices (`jobs/gram_verify.py`):
  `E1_minpoly_is_P_N`, `exact_sympy` and `exact_flint` (`E2_rank3`, `E3_caps` per worst cap),
  `interval_arb` and `interval_mpmath.iv` (`positive_definite`, `in_box_B`, `signs`), `relabelling`
  (from the labelling of `gram_exact.json` to image 0 of the local verification), `D_isolating_interval`
  (exact rationals), `verified`, `label` ("cross-verified (exact: sympy + FLINT; intervals: Arb + mpmath.iv)"),
  `atlas_level` (3), `statement`.

### `export/sphere/d3/cap_discrepancy_sup/n<N>/observations.json`: observations for critconfig-atlas
Written by `jobs/atlas_export.py` (extra inputs: search or atlas outputs with `points`). Top level
`{functional, N, observations:[…], shared_hashes}`. `functional` = `{id: "cap_discrepancy_sup",
definition, sense: "minimize", container: "sphere", d: 3, critical_point, gauge}`. Per observation:
* `kind` ("find"), `functional`, `container`, `d`, `N`, `name`, `X` (N×3), `source` (file, pointer, script, commit).
* `value`: list of descriptions `{id, level, status, value, note, evidence}`; level 0 double; for
  N5_best and N6_best also level 2 (`{interval: [lo, hi]}`) and level 3
  (`{minpoly (ascending, strings), isolating_interval (rationals), closed_form, decimal}`).
* `active` — the **active hypergraph**: vertices are the points, hyperedges the worst caps, each written as
  the over-full closed cap, `{boundary, interior, count, branches, weight_range, in_support}`
  (`boundary`: points on the circle; `interior`: points strictly inside; an under-full open cap is
  replaced by its complement; coincident caps are one hyperedge with several `branches`, the 2- or
  3-point sets that define it, named `up:i-j-k` / `low:i-j-k`). `code`: canonical code of the whole
  hypergraph. Level 0, or 2 for the proved minimizers.
* `weights` — the **weight space** W = {λ ≥ 0, Σλ = 1, Σ λ_b ∇f_b = 0} over the branches (KKT multipliers):
  `dim`, `support`, `ranges` ([min, max] of each λ_b on W), `maxmin` (the max-min point), `maxmin_value`,
  `signed_dim` (dimension of the signed solutions).
* `key_basis` = `{method, code, graph_hash}`: canonical code of the support hypergraph (hyperedges in the
  support of W); `graph_hash` = first 12 hex of SHA-256 of `sphere|d3|cap_discrepancy_sup|N<N>|<code>`.
  The atlas mints the ordinal of the key.
* `first_order` = `{rank, dim_quotient (2N−3), kernel_dim, sharp, multipliers_unique}`; `second_order`
  (only when kernel_dim > 0): eigenvalues of the Lagrangian Hessian on the kernel modulo rotations, and the
  numbers of descending, ascending and null directions (finite differences, level 0).
* `gram` (proved minimizers only): level 3, reference to `sphcap/data/gram_exact.json` with SHA-256 and the
  evidence file `certificates/gramcert_*.json`.

### `msolve/*.ms`: polynomial systems (text, msolve input format)
Line 1 has the variables, line 2 the characteristic (0), then comma-separated polynomials.
`N5_C2v.ms` and `N6_D3.ms` are the symmetry-reduced area equations whose elimination gives
P5 and P6. `N7_C2.ms` is being solved on w227.

### `sphcap/data/search/`
`search_N{9,10,11,12}.json`: the best classes of the N = 9–12 searches (w227, 2026-10-29; `jobs/search_parallel.py`,
12 rounds), one record per class: `{D, hits, active, rank, dimq, min_lambda, sharp, aut, sources, points, worst_caps}`.
Floating point (double precision). Input of `jobs/atlas_export.py` for `export/.../n9`–`n12`.

### Code (for reference, not data)
`sphcap/` (Python package), `csrc/` (C mesh program: `capcert.c`, interval-verified mode `ia.h`,
`rig.h`), and `jobs/` (search, identify, atlas, `local_cert.py`, `sym_cert.py`, `refine.py`).

## Getting server data to GitHub
There are two routes:

1. **Automatic.** Set up the deploy key described in `README.md`, then run with `PUSH=1`. This
   pushes `STATUS.md` and the small result JSONs every 10 minutes to branch `w227-status`.
2. **Manual snapshot.** Copy the JSONs into the `capdisc` branch with a commit, e.g. under
   `capdisc/data/` (ask Claude in the Discrepancy project).

For a website, the cleanest contract is a single aggregated export file,
`capdisc/data/site.json`: one entry per N with value, status, polynomial, points and worst
caps, plus the proof records. It can be generated from the files above by a small script
(not yet written).
